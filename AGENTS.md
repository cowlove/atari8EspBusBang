# Repository Guidance

Notes for anyone (people or agents) working in this repository: how the pieces fit, how we build, run and test them with `tools/`, the hardware on miner6 and a24, and what's still open. History lives in git (`git log -p AGENTS.md`); this file keeps what is true now, with dates where they help.

## The system in brief

- **main** (`main/`): an ESP32-S3 on the Atari's PBI/ECI bus. Core 1 runs the bus loop (`iloop_pbi`, `main/core1.cpp`) and serves the 6502 every cycle from main's memory map (MMU tables, `main/mmu.*`): base RAM, cartridges, extended banks, the PBI ROM (`main/pbirom.asm`). Core 0 runs everything else: the bmon loop (`core0Loop()`), PBI requests (`main/pbi.cpp`), SIO, the console. With core 1 serving, core 0 is "hot" (below).
- **The Sidecar** (`sidecar/`): a second ESP32-S3 joined to main by the i2slink (`components/i2slink`, a submodule; `components/sidecar_link`). It owns the network (WiFi, web server, telnet, SMB), the SD card, the boot configuration files, main's firmware updates (OTA over the link) and crash collection (main's core dumps), and it sequences main's boot (holds main's EN and the Atari's RESET at its own start, then releases main). The product always has a Sidecar; a standalone main build is kept for simple debugging and test setups (without WiFi, SMB, httpd or APT).
- **Board versions** (`-DBOARD_VERSION`, a CMake option, `main/pinDefs.h`): `1` (the default; the pool's espBusBang boards: A0-A15 on GPIO1-16, R/W on GPIO17) or `2` (the DevKitC carrier `hardware/espBusBangSidecar/` and the bare-module boards: R/W on GPIO15, A14-A15 on GPIO16-17, so core 1 gets page + R/W in one extract). The boot log prints `BOARD_VERSION`.
- **csim** (`csim/a800/`): main's and the Sidecar's real code against a fork of atari800 (submodule), in two modes: the default (atari800 runs the 6502 and calls main for PBI requests) and bus-cycle (`BUS_CYCLE=1`: every 6502 access goes through core 1's loop body, and core 0 runs as a coroutine).
- **Hot bus / cold bus:** the next section. Everything else in this file leans on it.

## The hot bus: why core 0 must stay out of core 1's way

**Hot bus** = core 1's bus loop is live, serving the 6502 from main's memory map. **Hot-bus code** = core 0 code that runs in that window: `core0Loop()`, `handlePbiRequestHot()`, the Sidecar call chain, i2slink polling, `LOGHOT()`, the sled, FAKE_SIO's harness. **Cold bus** = core 1 isn't serving: the bus is detached (core 1 on the transparent, do-nothing tables; `disableBus()`, `ScopedInterruptEnable`), the 6502 on its own native memory or parked in a loop of its own (the stack wait at `$0104`, the sled's catch); then core 0 may do anything (`handlePbiRequestCold()`, setup(), the exit report). Core 1's loop itself is heavily scrutinized; the danger is core 0.

**Why it's critical.** A 6502 bus cycle at 1.79 MHz is ~560 ns, ~134 ESP32 cycles at 240 MHz. In each, core 1 waits for phi2, reads the address at a fixed point (P1, ~cycle 11), looks it up in the MMU tables, and either drives the data lines and extSel_ in time for the 6502 to latch them (a read) or samples them (a write), at fixed cycle counts (P1-P6, counted statically by `tools/core1_cycle_count.py` on every build; tuned per machine class, with margins of a few tens of ns). There is no slack and no retry: a stall of a few cycles at the wrong point and the 6502 latches a wrong byte, executes a corrupted instruction, and crashes (typical symptoms: `-3 stackprog timeout`, `-2 IO timeout`, a BRK storm at `$0000`, `-10 CORE1_HANG`, failures that come and go with code layout). Core 1 can be stalled by core 0 through every resource the two cores share:

- **The peripheral bus (APB).** Core 1 drives the bus through GPIO registers (`GPIO_IN_REG`, `GPIO_OUT1_REG`, `GPIO_ENABLE1_W1TS/W1TC`); a peripheral access by core 0 (any: GPIO, UART, I2S/LEDC setup, timers) competes with them and delays core 1's. `esp_timer_get_time()` is a SYSTIMER peripheral access (snapshot, spin, read), not a cycle-counter read: it destabilized core 1 from the Sidecar path (2026-11-06). Hot code times with CCOUNT (`XTHAL_GET_CCOUNT()`, `esp_cpu_get_cycle_count()`); any `esp_*` call is suspect until its implementation is checked. The i2slink's data path is DMA into memory, polled from memory only: no peripheral registers from core 0 while hot.
- **Flash and PSRAM.** Both go through the shared MSPI cache: core 0 code or data there (a flash function, a `const` table, a format string, a `%s` argument, a string literal the linker merged into another file's flash string) means cache traffic and misses, and a flash write disables the cache altogether. Hot code is IRAM (`IRAM_ATTR`, `CORE0_HOTSPOTS_ATTR`, `noflash` objects in `main/link.lf`), its data internal DRAM (`DRAM_ATTR`, `DRAM_STR()`); main's malloc prefers PSRAM, so hot buffers are allocated internal (`HotStr` keeps the two strings core 0 reads hot there).
- **SRAM banks.** Internal SRAM is 32 KB banks; a bank serves one access at a time, and two cores in the same bank arbitrate. So core 1's loop (IRAM) and its hot data (the MMU tables, `mmuState`, the bmon rings, `d000Write`...) must sit in banks that core 0's hot code and data don't use: `main/core1_last.ld` puts `iloop_pbi` last in IRAM, unpadded; core 1's hot data (`CORE1_HOT_BSS`, `.core1_hot`) starts the bank after .bss, the gap before it returned to the heap (`mmuHotDataGapToHeap()`); core 0's busiest code is `CORE0_HOTSPOTS_ATTR` (explicit placement optional: `* (core0_hotspots)` in `link.lf`). Literal pools count too: Xtensa ld coalesces equal literals across files, so a value core 1 and core 0 both use (`mmuState`, `bmonHead`...) can land in core 0's pool, and core 1's `l32r` then reads core 0's bank every cycle (an `l32r` before P1 broke a build, 2026-11-09). The sled runs in RTC fast memory (`RTC_IRAM_ATTR`), which only core 0 executes from: its spin of up to 30 s shares no bank with anything. Core 0's interrupt stack may share a bank: interrupts are masked while hot.
- **Instruction fetch.** A core 0 poll loop refetches its instructions from its IRAM bank on every pass, a steady stream of accesses (an ifetch hotspot). Core 0's waits use `loopNezDelay(n)` / `loopNezPasses(n)` (`main/util.h`): a zero-overhead `loopnez` over a single `nop.n`, which spins without that fetch stream, with exact cycle counts (n <= 0 is still a scheduling barrier, `";;;"`; never `__sync_synchronize()`, a `memw`). Polls of a ring head are paced with it (e.g. `loopNezDelay(33)` between checks); core 1 uses it for its own delays too (fewer fetches, even at a cycle's cost).
- **Interrupts, the scheduler, the heap.** Core 0 runs hot with interrupts masked (`portDISABLE_INTERRUPTS()` before `core0Loop()`): an ISR would run flash code and touch peripherals at random moments. So no FreeRTOS calls, no `printf()` (its stdout lock aborts with interrupts masked: `LOG()` is cold only, `LOGHOT()` goes over the link with DRAM formats and arguments), no malloc (allocate before going hot, e.g. the exit report's ring copy), no dynamic-init statics (their guard is a flash `__cxa_guard` call), no `assert()` (flash strings: hot asserts are `-5` exits), and exits through `CORE0_EXIT_HOT(flag, "fmt", arg)` (formatted cold by `core0_exitHotFinish()` after `core0Loop()` returns; `core0_exit()` is cold only).

**The checks** (post-build, top-level `CMakeLists.txt`, every build; a failure fails the build):
- `tools/verify_core0_hot_calls.py`: from each hot root (`core0Loop`; the Sidecar call chain; `LOGHOT()`; the PBI request's Sidecar path; `SysMonitor::pbi`) walks every call and fails on code outside IRAM/ROM/RTC fast memory or vetted archives, a peripheral address in an `l32r` literal, or (`--check-data`) a flash/PSRAM data address. Declared cold calls (`--cold-call CALLER>CALLEE`): `handlePbiRequestHot>handlePbiRequestCold`, `handlePbiRequestHot>vTaskDelay` (the detached side of `ScopedInterruptEnable`), `core0Loop>core1Stalled`. Declared exceptions (`--peripheral-ok FUNC`, only in FAKE_CLOCK+FAKE_SIO builds): FAKE_SIO's five `BENCH_PINS` helpers (`ioMux`, `outSel`, `holdRwHigh`, `readDataLines`, `probeDataLines`), whose bench bank ops rewrite the fake bus's pins by design (no 6502 to crash). `fakeSio.cpp` is `noflash` but for `FAKESIO_COLD`.
- `tools/verify_iram_hotspots.py`: core 0's hotspots stay out of core 1's loop's IRAM bank.
- `tools/verify_core1_hot_data.py`: core 1's hot data stays out of IRAM code's and core 0's interrupt stack's banks (rerun after changing static sizes: less IRAM moves .data and .bss).
- `tools/core1_cycle_count.py --strict`: core 1's static cycle counts per sample point; no `l32r` before P1. After a `core1.cpp` change also dump the loop (`tools/dump_iloop_pbi.sh`) and look for in-loop `l32r`s.

**Not hot:** `setup()` before `startCpu1()` (core 1 not running; but it touches Atari pins: see the sled), the cold handler, the exit report. Core 1 must never load a word it just stored (a store-load stall broke the 130XE .5): test core 1 changes on .5.

## Rules for working here

- **Git:** stage files by name; never `git commit -a` (submodule pointers, notably atari800's, get dirty on branch switches); don't commit `dependencies.lock`/`sidecar/dependencies.lock` churn, binaries or test disk images (`.atr`, `.atr.gz`: keep them outside the repo, e.g. `~/atari-testdisks/` on a24). Work on `master` and push it; `newboard1` is retired (merged 2026-11-27 as `-DBOARD_VERSION=2`): don't push it.
- **The test pool (miner6) is the user's.** Its run loops run all the time (below). Deploying = push master, then fast-forward the checkouts (`git pull --ff-only`); the loops pick it up at their next run. Don't kill run loops, flash by hand, erase flash or switch the Tasmota plugs without asking. Stagger anything that boots several machines at once (~30 s apart: synchronized power-ons have interfered).
- **The bench pairs on a24 are the user's too:** don't run on them unless asked.
- **Serial flashing of main is by hand only**, with the Atari disconnected or off (ROM download mode needs MPD = GPIO46 low, which a powered Atari pulls). Machines with a Sidecar update main by OTA only.
- **eFuses:** `tools/efuse_check.sh` (run by boot.sh with the Atari off) burns `set-flash-voltage 3.3V` when missing (GPIO45 = D7 is the VDD_SPI strap); any other burn needs the user's explicit OK.
- **Develop and test in csim first:** `BUS_CYCLE=1 ./csim/a800/run.sh` (the bus-cycle mode: core 1's loop body serves every 6502 access, core 0's real `core0Loop()` runs as a coroutine; see csim below), before the bench or the pool.
- **Hot-bus code** follows the rules in "The hot bus" (below): no flash, PSRAM, peripherals, heap or interrupts, and care with core 1's SRAM banks; the post-build checks enforce what they can.

## Builds and runs: `tools/boot.sh`

Use `tools/boot.sh` for every hardware build/flash/boot rather than `idf.py flash`: it records each run under `stash/` (below). Always pass `-t <sec>` (the run's length). `idf.py fullclean` fixes a stale build cache (generated state only).

**Modes** (`Usage: boot.sh [-q|-qq] [-p] [-sc [--erase-core] | -net <sidecar host>] [-t run_seconds] [--noflash] [idf.py args...]`):

| Mode | What it does |
|---|---|
| (plain) | Build main, flash it over main's USB (`PORT`): app, bootloader, partition table, and main's spiffs when its image changed (`flash_spiffs.sh -u`, `FLASH_SPIFFS_AFTER=no-reset`); power the Atari on at main's `BOOT COMPLETE` (or blind after 10 s); capture main's USB console to DONE. Builds without the Sidecar unless given `-DSIDECAR=ON`. |
| `-sc` | Through the Sidecar (`tools/boot_sidecar.sh`): build main (with `-DSIDECAR=ON`) and the Sidecar; flash the Sidecar app plus its spiffs with main's images staged (`sidecar/flash_spiffs.sh`, on `SIDECAR_PORT`); reset the Sidecar, whose start reboots main; main's boot report shows a different app token, so it OTAs the staged `app.bin.gz`; capture the Sidecar's console (main's output arrives over the link). main's own spiffs image is rebuilt when its sources change but not flashed; nor are main's bootloader and partition table. Restaging the Sidecar's spiffs wipes its `/spiffs/config`. |
| `-sc --erase-core` | As `-sc`, with the Sidecar built `-DERASE_CORE=1`: deletes stored cores and erases main's instead of fetching it (a board's bring-up, or a core that can't be fetched and loops). |
| `-sc -qq` | Build and flash nothing: reset the Sidecar over its USB (esptool `run`) and capture: both boards boot afresh on the images already there (`tools/bench_soak.sh` loops on it). |
| `-net <host>` | Over the network only (`tools/boot_net.sh`): build both apps, upload `main.bin.gz` and `sidecar.bin.gz` to the Sidecar's `/sd/update` (else `/spiffs/update`), send `update`, follow `/console/out` to main's DONE. The Sidecar's bootloader, partition table and spiffs still need one USB `-sc`. |
| `-p` | Test-pool mode: `HW_TYPE=TESTPOOL<N>` from the checkout's `.N` suffix. |
| `-q`, `--noflash` | Skip steps (quick reflash; build only). |

**Build knobs.** `-D` arguments go to CMake. String defines get their quotes added (`-DBOOT_CONFIG=SDX_AUTO`, `-DHW_TYPE=`, `-DCART_IMAGE=`; not the split form `-D BOOT_CONFIG=...`). `tools/clear_build_defines.sh` (every boot script) clears from the CMake cache each knob `main/CMakeLists.txt` reads that this run doesn't pass, so nothing carries over and builds stay incremental: **a new `-D` knob goes in that file's define list.** The Sidecar's knobs go through `SIDECAR_DEFINES` (cleared the same way by boot_sidecar.sh). Top-level CMake options: `SIDECAR`, `SIDECAR_LOOPBACK`, `SIDECAR_LOG_ONLY`; main's: `BOARD_VERSION`, `FAKE_CLOCK`, `FAKE_SIO` and the define list. Builds carry no compile time, so an unchanged main isn't reflashed by OTA; `-DBOOT_TOKEN=<n>` forces a new image (`SIDECAR_DEFINES=-DBOOT_TOKEN=<n>` for the Sidecar). `boot.sh` refuses `FAKE_CLOCK`/`FAKE_SIO` builds (and `-qq` of a cached one) on machines whose `tools/config` sets `MQTT_HOST` and `TAS`: they drive bus pins and would fight a real Atari.

**`tools/config`** (untracked, per checkout): `PORT`, `SIDECAR_PORT` (by-id paths: `/dev/serial/by-id/usb-Espressif_USB_JTAG_serial_debug_unit_<MAC>-if00`), `SIDECAR_HOST`, and for power control `MQTT_HOST`, `TAS` (the Tasmota plug), `MQTT_POWER_TOPIC`. It re-exports over the environment: a test with a dummy port still flashes the configured one.

**Captures (`stash/`).** `boot.sh` runs under `tools/run_capture.sh` (`tools/RUN_CAPTURE.md`): every run leaves `stash/<YYYYMMDD.HHMMSS>.<git version>.<diff hash>.mainapp.*`: `.output` (the console), `.git_diff` (staged and unstaged changes to tracked files; untracked files only by path and hash), `.git_version`, `.git_status`, `.cmd`, `.metadata`; `stash/mainapp.output.latest` is the live log. Crashes add `.core.bin.gz`, `.coredump_info`, `.crash.tgz`, `.elf.gz`. Every main ELF built is kept in `stash/elf/<sha256>.elf.gz` (`tools/elf_archive.sh`, newest 40) for decoding old cores. boot.sh may leave serial readers running: check for stale `cat`/`cat_until` before another capture.

**Power** (machines with `MQTT_HOST`/`TAS`): `tools/power_on.sh`, `power_off.sh`, `power_set.sh ON|OFF|STATE` (waits for the plug's confirmation). boot.sh powers the Atari off at any exit (every EXIT trap in boot.sh, boot_sidecar.sh, boot_net.sh; INT/TERM/HUP too) and on at main's `BOOT COMPLETE` (`tools/power_on_when_up.sh`; `-sc`: also at the Sidecar's `BOOT_EXPECTED_COMPLETE`, 5 s after a normal boot report; never blind: an OTA may be running; gives up after 120 s). Main prints `BOOT COMPLETE` early in setup(), before core 1 starts (the sled makes either order safe, below), so the Atari usually powers on during main's setup.

**DONE lines.** Every run ends `DONE <sec> <flag> <reason>`, flag < 0 a failure (the pool's scripts parse it). Main's flags: the exit reason's leading number: 0 run time reached, 1 exit hotkey, 2 exit command (`tools/halt.sh` sends `exit 2`), 3 user halt, 4 telnet exit, 5 ProcFS HALT file, 6 no bus clock (the sled loop test with the Atari off); -1 watchdog, -2 IO timeout, -3 stackprog timeout (a wedged 6502), -4 repeat reads, -5 a hot assert, -6 startup timeout, -7 sled loop test failed, -9 TEST_FAIL_EXIT, -10 CORE1_FAULT/CORE1_HANG. The Sidecar's (reason `Sidecar: ...`, `<sec>` since the boot report): -11 main crashed (core fetched), -12 main silent on the link (reset, no core), -13 silent and no boot report after the reset, -14 silent (csim), -15 ERASE_CORE failed. Main's lines in its first 10 s carry LOG()'s `[NNNNN] ` boot stamp (BOOT COMPLETE always, DONE in a short run): a pattern anchored on one of main's lines takes `^(\[[0-9]{5}\] )?` (the Sidecar's own lines are never stamped). After DONE the capture reads on to the Sidecar sampler's `SAMPLER_PERIOD_END ... stop` (10 s at most). **`-sc` exit codes:** 3 main never ran the staged app, 5 it runs another build, 6 crashed (core fetched and bundled), 7 silent on the link.

**Crashes and cores.**
- **Failure exits dump core:** a negative exit prints its report and DONE, then panics (`EXIT_COREDUMP`), leaving a core of the failing state. Plain boot.sh reads on to `Rebooting` and runs `tools/crash_bundle.sh`.
- **With a Sidecar** main's panic text never reaches the capture; the Sidecar learns of the crash from main's next boot report (a core it hasn't stored), puts main in diagnostic mode, fetches the core gzipped into `/spiffs/core/main-<token>.core.gz`, has main erase its copy (EraseCore), prints `COREFILE_AVAILABLE ...` and `DONE ... -11`; `crash_bundle.sh --sidecar` dumps the Sidecar's spiffs (esptool), extracts the core (`tools/spiffs_extract.py`) and decodes it. A core from an older build is decoded against `stash/elf/` (`tools/core_app_sha.py`, `CORE_ELF_MISMATCH`). A `Backtrace:` on the Sidecar's console is the Sidecar's own crash (its coredump partition; decode against `sidecar/build/sidecar.elf`).
- **Core 1 faults:** core 1 runs on the ROM's vectors; `core1ExceptionHandler()` (installed in the ROM's xtos handler table) records EPC1/EXCCAUSE/EXCVADDR and parks core 1; core 0 checks every second that bmon moves and, 3 s without (phi2 running), exits `-10 CORE1_FAULT ... at PC` or `-10 CORE1_HANG ... core 1 PC` (from the assist-debug PC record).
- **Main's link watchdog, on the Sidecar:** armed by a normal boot report, reset by any command from main (at least every ~2 s), disarmed by DONE; silence for 30 s beyond main's own timeouts prints `MAIN_LINK_SILENT`, resets main into diagnostic mode, and ends the run (core fetched, exit 6; or `-12`, exit 7).
- **Test knobs:** `-DTEST_PANIC=<n>` (core 0 crashes after n s, once per boot not after a panic), `-DTEST_FAIL_EXIT=<n>` (`-9`), `-DTEST_CORE1_FAULT=<n>`, `-DTEST_CORE1_HANG=<n>`, `-DTEST_CORE0_HANG=<n>` (core 0 spins masked: silent).

**Other tools.** `tools/halt.sh` (ask a running main to stop: `exit 2` on its USB and/or `main exit 2` through the Sidecar's console); `tools/screenshot_png.py <log> <png>` (renders the shutdown report's screenshot); `tools/bench_soak.sh` (`-sc -qq` runs back to back); `tools/bench_net_soak.sh [-H host] [-t 180] [-n runs] [-m both|main|sidecar]` (`-net` runs with new BOOT_TOKENs each, every run an OTA of both apps; `stash/bench_net_soak.summary`; stop with `touch stash/bench_net_soak.STOP`); `tools/core1_cycle_count.py` (core 1's static cycle counts per sample point, run after every build); `tools/verify_*.py` (the post-build checks, below).

## The test pool on miner6

Six Ataris with boards on `miner6.local` (`ssh miner6.local`; plain `git@github.com` remotes, pulls work through the forwarded agent). Checkouts `~/src/atari8EspBusBang.<N>`, N = 1-6, all on `master`. "Fast-forward machine 3" means `git -C ~/src/atari8EspBusBang.3 pull --ff-only` there (after pushing). `tools/testpool_forEach.sh "<cmd>"` runs a command in all six.

**What is where: `docs/testpool.md`**, a table the user updates when hardware moves between slots (each slot's Atari, main board and version, MACs, plug, quirks). Read it before reasoning about a machine; don't trust older notes about which Atari is in which slot.

- **Run loops:** each checkout runs `tools/testpool_runloop.sh` (the user's, always running), which runs `tools/testpool_run.sh` over and over: one `boot.sh` run per pass with that machine's line (`-sc` for .3/.4/.6, `-DBOARD_VERSION=2` for .3/.4, `-DBOOT_CONFIG=SDX_AUTO`, `-p -t 20000`, plus the current test's knobs: `SOAK`/`LOOP` at the top of the script). Changing what the pool runs = editing `testpool_run.sh`, push, fast-forward.
- **Monitoring:** each machine's `stash/` (`mainapp.output.latest` is the run in progress); tally DONE lines across `stash/*.mainapp.output`. Check a fresh deploy ~90 s after POWER ON for `io:` lines, and report boot failures early.
- **Stopping a machine** (only when asked): `tools/halt.sh` in its checkout (main ends with `DONE ... 2`), then the run loop starts the next run unless it's killed: killing a loop is the user's call.
- **Bootloaders:** main's bootloader (with its bus sample hook, below) reaches a board only by a USB flash: plain boot.sh does it (.1/.2/.5); the Sidecar machines need a by-hand bootloader flash (the user's).

## The a24 bench

On a24 (this machine), bench pairs with their own letter-suffixed clones (`~/src/atari8EspBusBang.a`, `.b`), each with its own `tools/config` and `stash/`; not to be used unless asked. Pair A: the DevKitC carrier (board version 2), main N8R2 FC:01:2C:2D:91:68, Sidecar N16R8 7C:4F:AD:BD:1B:A4. No Atari: bench runs are `FAKE_CLOCK` builds (core 0 drives a fake clock, R/W and A0), e.g. `boot.sh -sc -t 30 -DFAKE_CLOCK=1 -DFAKE_SIO=1 -DBOARD_VERSION=2 -DBOOT_CONFIG=BENCH` (FAKE_SIO: core 0 plays the 6502's PBI side; PASS/FAIL in its report). A Sidecar OTAs a USB-flashed main back to its staged app: stage first. Identify a board by `esptool flash-id` (16 MB + 8 MB PSRAM = a Sidecar).

**OpenOCD on a Sidecar** (udev rule installed): `openocd -c "set ESP_RTOS FreeRTOS" -f board/esp32s3-builtin.cfg -c "adapter serial <MAC>" -c "gdb_memory_map disable"`, then `xtensa-esp32s3-elf-gdb -ex "target extended-remote :3333" -ex interrupt -ex "thread apply all bt" sidecar/build/sidecar.elf`. With memory protection on (the default) a gdb attach resets the chip: turn `CONFIG_ESP_SYSTEM_MEMPROT` off for such a session. Breakpoints in flash need `hbreak`. With a USB host attached IDF treats the chip as debugged: a panic breaks instead of rebooting.

## Talking to the Sidecar

- **Console** (its USB, `SIDECAR_PORT`; also the web): `reset` (main's EN), `reboot` (a safe reboot: main parks the 6502 first, below), `diag` / `diag ota` / `diag panic` (flags for main's next boot report; `reset` to apply), `main <line>` (a line to main's console), `atari hold|release|reset [<ms>]`, `setflags <names|number>` (SetFlags into main: `interrupt` 0x1 raises one PBI interrupt, `screenshot` 0x2; retried 3 s), `config ...` (below), `update [<dir>]`, `flash ...` (below), files: `ls`, `rm`, `cp`, `hash`, `gunzip`, `sdformat yes`, with `main:` and `sidecar:` prefixes (main serves its files only in diagnostic mode), `sample report`, `slottune on|off`, `corehold on`, `lockstress ...`. The first command after a boot sometimes fails on startup garbage in the input buffer (open, minor).
- **Web** (`sidecar/main/sidecarWeb.cpp`'s header lists the API; one request at a time): files `GET /files/get|hash|ls?p=`, `curl -f --data-binary @<local> "http://<sidecar>/files/put?p=/sd/<name>"` (`.part` then renamed; missing directories made; replies size and SHA-256), `POST /files/rm?p=`, `GET /files/status` (whether main's files are reachable: diagnostic mode only; the FILES page grays "Main flash" out otherwise); console `POST /console/cmd` (each body line as if typed, echoed `web> ...`), `GET /console/out?since=<offset>[&wait=<ms>]` (a 64 KB ring of everything the Sidecar prints, main's output included; `X-Console-Next`, `X-Console-Lost`), `/console` (interactive); `/config` (below); `/screen` (main's screenshot on a canvas; Capture posts `setflags screenshot interrupt`); `POST /debug/abort`, `GET /debug/coredump` (the Sidecar's own).
- **Files over USB:** `tools/sidecar_xfer.py put|get <local> <remote>` (the Sidecar's `/spiffs` and `/sd`; SHA-256 checked; nothing else may hold the port); `tools/main_xfer.py put|get <local> /spiffs/<name>` (main's spiffs, via the Sidecar's `/sd` and `cp main:`; main in diagnostic mode). This is how main's spiffs is updated on a Sidecar machine: `-sc` and `-net` don't flash it.
- **Updates:** `update [<dir>]` (UpdateJob): `main.bin.gz` and `sidecar.bin[.gz]` from `<dir>`, else `/sd/update`, else `/spiffs/update`. Main first (the Firmware object points at the found image; main reset; the usual OTA; a stale staged `app.bin.gz` is removed once main runs the new one), then the Sidecar writes its own spare OTA slot, switches and restarts. Ends `UPDATE_DONE` or `UPDATE_FAILED <why>`. A new Sidecar app is on probation (rollback enabled) until healthy for 30 s with WiFi up; else the bootloader goes back after 180 s. `MAIN_UPDATE_STALLED`: no chunk asked for 15 s resets main. A wire-format change to the link strands an old main behind a new Sidecar (no OTA across it): update through the old Sidecar first, or flash by USB.
- **Serial-flashing main from the Sidecar** (by hand only, main's board off the Atari; refused while the bus shows activity): `flash main yes [<spiffs image>]` writes the bootloader, partition table, otadata and app staged in `/spiffs/main/`; `flash spiffs yes <image>`; `.gz` inflated as sent. Main's spiffs image: `tools/flash_spiffs.sh --noflash` builds `spiffs/spiffs.bin`.
- **Telnet** is served by the Sidecar (the Stream link command); main keeps only the screen half (`telnetScreen.cpp`).

## Boot configurations

## Design notes

### Startup: the sled (`main.cpp` `sledPrepare()`, `sledRun()`)

The full story (the design, why each piece is the way it is, the failures that shaped it, testing): **`docs/COLD_START.md`**.

Main may come up under an Atari that is off, just powering on, running its OS natively, or parked by a previous main. It handles them all without a halt or reset line (the PBI/ECI RST pin is output-only, and a 130XE's ECI "HALT" is ANTIC's output, not RDY). Every build with a real 6502 (`A8BB_SLED`: not FAKE_CLOCK, not csim's default mode, which go straight to the map) does this:

1. `setup()` leaves every Atari-facing pin quiet: data pins inputs (core 1 enables them per cycle it serves), open-drain lines released before their pads are enabled (`pinOpenDrainIdle()`), halt_ set up but never driven at startup (core 1's halting writes still use it). Core 1 starts on the transparent map (`mmuStateDisabled`: it drives nothing, native memory answers) and fills the bmon rings.
2. `threadFunc()` logs `BOOT_TIME: <ms> ms of uptime ...` (the last cold moment; `esp_timer_get_time()`, the system timer from the chip's reset), masks interrupts, and `core0Loop()` starts with `sledRun()` (RTC fast memory, hot).
3. **No bus clock for 10 ms** (the bmon heads still: the Atari off): the real map goes in at once; the 6502 boots onto it at power-on (`SLED: no bus clock ...`). The sled loop test skips this and waits for a clock.
4. **A clock:** the flood goes live a pointer at a time: `$0000-$7FFF` reads `$4C` (writes to dummy RAM; page 0 a scratch page; page 6 main's base RAM with the stub). Any fetch there is `JMP $4C4C`, which loops; RTS/RTI land there; every RAM vector is `$4C4C`. Escapes: ROM or cartridge code spinning with NMIs and IRQs off (AltirraOS's reset-time init lands when it ends, ~160 ms after power-on; the XL OS's init is untested). A parked 6502 (below) is caught at its next fetch (0 ms). The report tells which from the reads before the flood: `SLED: before the flood the 6502 was parked at $0104 (the safe reboot's stack wait)` / `parked at $3000` / `running`.
5. Caught (24 reads in a row at `$4C4C-$4C4E`, within 3 s of clocked time, 30 s at most): the JMP's operand is turned to `$0600` a byte at a time (`$4C00` is still the flood); the stub (SEI, CLD, NMIEN 0, a mark, a spin on its go byte) runs; PUPBT1 cleared, COLDST set, the real map in (`enableBus()`); `core0Loop()` sets the go byte after its backlog discard: the stub sets up the PIA as the OS does (PBCTL `$38`, DDRB `$FF`, PBCTL `$3C`, PORTB `$FF`: a 6502 caught right after its reset finds PBCTL 0, where a bare PORTB write made every line an output driving `$00`, the OS ROM out, a BRK storm) and does `JMP ($FFFC)`: a cold start onto main's map.

Every reset is a cold start: `PBI_INIT` clears PUPBT1, so the OS never warm-starts onto state that didn't survive (main's PORTB/`$D1FF` copies, SDX's banks). Results print cold (`sledLandingReport()`: the exit report and the safe reboot's handler; a Sidecar build also sends a `LOGHOT()` line at once). Opt-in debugging: `-DBOOT_BUS_PROBE=1` (core 0's 5 ms bus samples through setup and before a restart, `BUS_PROBE ...`), `-DSLED_CAPTURE=1` (the first 128 writes after the release and read-ring snapshots, `SLED_CAPTURE:`). No status LED on board version 1 (GPIO48 is R1 to the Atari's RESET there). csim: power-on caught after 161 ms, reboots parked at `$0104` caught in 0 ms.

### Safe reboots

A plain main reset under an Atari running on main's memory crashes it (its memory vanishes mid-instruction). The Sidecar console's `reboot` (also Boot now and `update`) posts SetFlags `Reboot|Interrupt`; main's next IRQ call goes cold (the detach-safe reissue), and `handlePbiRequestCold()`'s IRQ branch, with the 6502 in the stack wait in its own page 1 and the bus detached, calls `safeRebootParked()`: RebootReady to the Sidecar, which resets main (main restarts itself after 3 s without; standalone at once; the Sidecar resets anyway after 5 s). The next boot's sled catches the parked 6502. Resets of a hung main (link watchdog, ERASE_CORE, a stalled OTA) stay plain.

**The stack wait** (`SAFE_WAIT`, `pbirom.asm`; every detach-safe PBI call): copied to `$0100`: `STA ESP32_IOCB_REQ,y` (the request), `SEC`, `BCS *` at `$0104`, `RTS`. `handlePbiRequestHot()` waits for 4 fetches of `$0104` in the read ring (counted from after the request; none in 1 s: `-3 stackprog timeout`, a wedged 6502), then writes an RTS over the BCS. The loop polls nothing and writes nothing, and its bytes have bit 5 set (D5, below).

**`esp_restart()` leaves core 1 running:** in this single-core build it resets CPU 0 only, and IDF stalls core 1 only in the new app's startup, after the ROM and bootloader have rewritten IRAM/DRAM under it. `rebootRestart()` calls `core1StopForRestart()` first (`disableBus()`, core 1 stalled, held in reset, clock gated, every bus pad an input). An EN reset (the Sidecar's) resets the whole chip. Any other `esp_restart()` under a running Atari (an OTA's) needs the same: open.

### Boot pin hazards: GPIO43 = D5 and GPIO45 = D7

Data is `Pin<38, 8>`, GPIO38-45 = D0-D7; the board is out of pins, so they stay.

- **The ROM drives D5 high through main's reset** (GPIO43 is U0TXD at reset; the ROM sets up UART0 and clears that pad's hold). On the 800XLs this wins over the DRAM: a 6502 parked at `JMP $3000` left its loop within ~10 ms of every restart (fetching `JMP ($3020)`, presumably); the 130XEs and the 600XL never minded. Holding every other pad through the reset (`-DRESTART_PAD_HOLD=1`, RTC pad hold) changed nothing; parks whose bytes have bit 5 set (`BCS *`, `$B0 $FE`) survive every restart. **Anything the 6502 runs while main resets must tolerate D5 high.** The real fix is hardware (D5 off GPIO43, or a series resistor/buffer).
- Also handled: USB-Serial-JTAG is the only console (UART0's logs used to toggle D5 every boot); the ROM banner is off (`UART_PRINT_CONTROL`); the bootloader hook (`bootloader_components/a8bb_boot_pins/hooks.c`) makes GPIO43/44 inputs first thing, samples the bus (both pin maps; "park loop seen" at `$3000` or `$0104`), releases any pad hold, and passes what it found to main in `RTC_CNTL_STORE0_REG` (main logs `boot pins: ...` and `BOOT_PIN_WARNING` if either pad was an output). It ships in the bootloader: USB flashes only.
- **GPIO45 = D7 is the VDD_SPI strap:** `efuse_check.sh` burns `set-flash-voltage 3.3V` on any S3 without it (not 1.8 V PSRAM parts). GPIO46 = MPD is a strap too: ROM download mode needs the Atari off.

### bmon: core 0 must keep up

Core 1 pushes every bus cycle but refresh into the write ring (`bmonArray`, 512) or the read ring (`bmonRdArray`, 256), and never waits; core 0 drains them (a write, then up to `bmonRdBatch` reads) and must drop nothing, except inside `handlePbiRequestHot()`, where the backlog is discarded on return: safe only because the 6502 is then in the PBI driver with interrupts masked and makes no write core 0 must act on (the `$D1FF`/`$D301` writes that assert halt_: a lost one hangs the 6502). Full statement at `bmonArray` in `main/bmon.h`. With the bus detached core 1's entries are gibberish (why the queue is cleared on re-attach). No dynamic-init statics in `core0Loop()` (their guard is a flash call).

### Test knobs for startup and reboots

- `-DSLED_LOOP=<sec>`: the sled's unit test: flood, catch, stub, an empty-RAM map (main's `$0000-$07FF` only), the release, `<sec>` s of the OS running, again; 12 cycles, `-7` at the first failure. **`-DSLED_LOOP_RESTART=<n>`** as well: one cycle a boot, then the stub (go 2) parks the 6502 at `$3000` in native RAM (`BCS *`; `-DSLED_PARK_JMP=1`: the old `JMP $3000`) and main restarts under it (`-DSLED_RESTART_SYS=1`: a system reset), n cycles across restarts (`0 SLED_LOOP: all <n> cycles passed, main restarted under each`).
- `-DRESET_AFTER=<sec>`: a safe reboot that many seconds into the run, once (an RTC mark; with a Sidecar every boot, since its EN reset clears RTC memory); `-DRESET_REPEAT=1`: a soak, every boot (main restarts itself, keeping its RTC record of boots and seconds; the run ends with its usual DONE). The pool's `SOAK` is `-DRESET_AFTER=60 -DRESET_REPEAT=1`.
- With a Sidecar, a main restart is preceded by `RestartingSelf`: the Sidecar's sampler prints `REBOOT_TIMELINE` (2 s of 5 ms buckets: phi2 falls, writes, extSel_ cycles, each bucket's first write).
- `-DIRQ_JAM_TEST=<sec>` (core 0 holds irq_ from setup(); `irqJam()`/`irqUnjam()`): built during the sled's design, unused by it. Lifting a long jam is unsafe (the OS's nested deferred VBIs all resume).

### Other settled design points

- **Diagnostic mode** is decided only in the Sidecar's BootStatus reply; OTA and core fetch run there. The utility tasks poll the link every 100 ms (`takeMainFlags()`); a new Sidecar-initiated event goes through SetFlags, polled at ≥10 Hz within the bmon keep-up rule.
- **What stays on main** (settled 2026-11-24): minimal disk image support and the proc files; SIO is proxied to the Sidecar; WiFi and SMB only behind `CONFIG_A8BB_WIFI`; APT is the one piece still expected to move.
- **SMB recovery** (`components/disk_image/diskStitchSmb.h`): a failed operation checks the server (a stat, not `smb2_echo()`, whose check is inverted in this libsmb2), reconnects and retries once; backs off 2-30 s while unreachable. A connection belongs to the one stitched disk that made it, used only from the Sidecar's service task (no lock).
- **Refresh:** refresh cycles stay out of bmon's read ring (refresh_ on GPIO21); core 1 still drives data on a refresh cycle in a mapped page, harmless (the DRAM's outputs are tri-stated, CAS_ inhibited).
- **Screenshots:** the shutdown report prints `dumpScreenshot()` (registers, display list, screen memory, charset; `main/screenshot.cpp` documents it), rendered by `tools/screenshot_png.py` (native RAM and the OS ROM read `--`: `--font` for the OS font). The Sidecar's `/screen` gets one on demand (`SidecarMainFlag::Screenshot`, the `Screenshot` stream channel). Not in FAKE_CLOCK builds; csim bus-cycle only.
- **LOG** goes synchronously over the link from core 0 only (line-buffered SerialOut; not re-entrant); `LOGHOT()` is the hot-safe form (DRAM formats and arguments).
- **The Sidecar's stdout** is a line-buffered picolibc stream feeding the web console ring (`consoleTee.c`; spinlock, printf from anywhere), not `funopen()` (it ignored `_IOLBF`).

## Link timing (`components/i2slink/src/i2slink.c`)

- **The component** is its own repo (https://github.com/cowlove/i2slink, a submodule since 2026-11-23): a change is a commit there, pushed, then a pointer bump here (`git submodule update --init components/i2slink` after pulling). Keep it project-free: no a8log, `CONFIG_A8BB_*` or project names in API, code or comments; logging through `i2slink_config_t::log`, hot placement through `I2SLINK_HOT_SECTION`, csim hooks through `I2SLINK_SIM_*`. GPL-2.0; `examples/pingpong` runs on one bare board (LOOPBACK).
- **Slots:** each end's TX DMA loops over its cycle (468 bytes, ~374 us); a new version leaves when that DMA reaches a fixed point, the end's slot. A request waits 0..1 cycle for its slot.
- **Variable-length frames:** a version uses only its length (trailing zero words trimmed); CRC and T follow it. A wire-format change: no OTA across it.
- **Slot tuning** (the Sidecar, on by default): measures each fast response's wait to its TX slot (from the TX GDMA's descriptor register, `I2S_DMA_TX_DESC_LEAD` = 2 descriptors ~56 us ahead) and moves its frame where a window of 32 would have waited least; two windows must agree within 40 us. **Announced moves:** the Sidecar announces a move in its report word and moves when main echoes (250 ms timeout); main, on framing failure, tries its old marker moved by the announced amount.
- **The ack skip:** the Sidecar doesn't ack a command it answers at once; the response carries the ack.
- **Wire rate: 200,000 frames/s, RX on the rising edge** (decided 2026-11-20 until the carrier boards are swept: every wiring change moved the clean maximum; 312,500 relocked constantly with RX on GPIO18 next to R/W).
- **A round trip** (a24, Nop, tuned, measured at 312,500: min 442 / mean 641 us): main's slot wait (0..374), two hops of ~170-205 us (~58 us on the wire, ~147 us the I2S TX FIFO), the Sidecar's ~75 us (its bit-shift render ~60 us), a ~25 us margin. Bulk fetches: 3 wire cycles a chunk (233.6 kB/s), bound by main's ~350 us a chunk.
- **Measuring:** `-DLINK_TEST=<n>` (main: Test-object fetches, timed Nop and SIO-status round trips, a write-later sweep); `-DSIDECAR_LOOPBACK=ON` (+ `-DNO_REFRESH=1` to keep a single board's USB) times the one-way pipeline. Sidecar knobs (`SIDECAR_DEFINES`): `-DSLOT_TUNE=0`, `-DSLOT_FAST_US=<us>`, `-DSLOT_TRACE=1`; stats lines only with `-DI2SLINK_STATS_LOG=1` (boot.sh -sc passes it on), main's bmon delay line with `-DBMON_DELAY_LOG=1`.
- **Soaks:** `csim/a800/seed_soak.sh`; `tools/bench_soak.sh`.
- **Open:** the wire rate on the carrier boards; main's per-chunk work; a cheaper Sidecar render; per-command lengths.

## ROM core 1 boot DRAM

`startCpu1()` boots core 1 through the ROM, in DRAM single-core IDF otherwise recycles. `main/main.cpp` reserves 0x3fceb710-0x3fceee34 and, once core 1 reaches `app_cpu_main()`, returns all of it but `.data_xtos` (0x3fcedf60-0x3fcee378) to the heap: 13,068 of 14,116 bytes. Fragile:

- **It relies on** (ESP-IDF 6.1, ESP32-S3 rev 0.2, 2026-11-06): the ROM's core 1 boot writes only `_Pri_4/_Pri_5_HandlerAddress` (inside `.data_xtos`); core 1 keeps the ROM's vectors (faults dispatch through `.data_xtos`, hence reserved; core 1 also installs its own handler there, above); `startCpu1()` runs once per boot and the panic hook stops core 1 rather than restarting it.
- **Guard:** before `startCpu1()` the reclaimable parts are filled with 0xa5 and reclaimed only if the pattern survives (`Reclaimed 13068 bytes of ROM core 1 boot DRAM`; else `ROM DRAM reclaim: ... keeping the span reserved`). It can't see a later dependency: rerun the probes after any IDF, ROM-ELF or chip-revision change, or a change to `startCpu1()`, `app_cpu_init()` or the panic hook.
- **Probes** on a bench board: `PORT=<by-id> ./tools/boot.sh -t 40 -DFAKE_CLOCK=1 -DBOOT_CONFIG=BENCH -DROM_BOOT_PROBE=N` (the define is cleared by the next run): `1` what core 1's boot changes (expect 0 bytes) and an 8 KB allocation landing in the reclaimed part; `2` that, then `abort()` (core dump, reboot, same again, DONE); `3` a core 1 store to address 4 after 5 s (the core 1 Guru report, PC in `app_cpu_main`; no DONE: cap with `timeout`, kill leftover readers); `4` = `3` without the reclaim (should match). ROM layout: `xtensa-esp32s3-elf-objdump -h ~/.espressif/tools/esp-rom-elfs/*/esp32s3_rev0_rom.elf`, `nm -n` for `xtos_exc_handler_table`.
- **If the guard fires or a probe disagrees:** stop reclaiming (drop `reclaimRomAppCpuBootDram()`), re-measure. Untried alternative: boot core 1 from an early `ESP_SYSTEM_INIT_FN` and park it in IRAM until `setup()`.

- **One proc: file set, two doors:** the `ProcFsFile`s (`diskStitchProc.h`, `procFsNodes.h`) reachable as a disk (today) and as a CIO device through `CioDispatcher` (mind `P:`).
- **Re-enable the native block** on the detach-safe reissue path only (`SETUP_NATIVE_BLOCK` in pbirom.asm, `PBICMD_UNMAP/REMAP_NATIVE_BLOCK`): the screen and display list copied to native RAM at `$1000` so ANTIC shows something while main detaches. Old question: `PBICMD_WAIT_VBLANK`/`NOP` hung in that sequence. Test on a 600XL.
- **Halt only for PSRAM swap-ins:** today every `$D3xx` write halts (~750 halts/s on .1); a per-PORTB-value halt mask beside `extBanks[]`, kept by core 0, would halt only for PSRAM-resident selects. Needs room in core 1's write path; measure halts/s and an SDX benchmark before and after (watch the late PORTB switch and the resume-halt race).
- **Read ring filter:** keep only the reads core 0 uses (page `$D5`), with a switch to keep all for traces of a wedged 6502 (the sled and the stack wait need `$4C4C`, `$0104`: keep those).
- **csim's main reset across boot configurations:** a sweep of Boot now through 11 configurations died after BANKTEST → CONAN (a CIM at `$C005`); suspects: shadows or ext-bank state `mmuStaticReinit()`/`setup()` don't reset.
- **Unconfirmed on a real Atari:** serial commands to a standalone main (`halt.sh`'s `exit 2`, read only in the PBI handler); a panic's backtrace and core in a standalone crash bundle; SetFlags `interrupt` (tested in csim only). The Sidecar's `flash` should also check main's ROM chip ID against the expected board.
